# 实现方案：新访客观察期、首页提示条、导航排序、屏蔽词预设（v1.10.0）

> 给实现者（AI 编码助手或人类开发者）：请先通读本文和根目录的 `AGENTS.md`，再动手。
> 本版本不涉及 D1（D1 迁移见 `docs/plans/d1-migration.md`，是 v2.0 的事）。
> 行号以写方案时的代码为准，代码有变动时请按函数名定位。

## 背景

线上出现了这样一个广告号：2023 年注册的老账号，**真人通过了图形人机验证**，第一条消息就是广告。

现在的护盾里，访客一旦通过验证（默认 30 天免验证），之后的消息**只检查屏蔽关键词**。`assessIncomingRisk`（`src/worker/antispam.js`）里的链接、转发、媒体等风险信号，只在「还没验证」时用来决定验证强度。而这位站长**没有设置任何屏蔽关键词**。

本版本四项改动：

1. **新访客观察期**：刚通过验证的访客，可疑消息先扣下，等站长审核。
2. **首页提示条**：名片下的「站长速览」卡片换成一行提示条，统计挪到「访客」页。
3. **导航顺序可自定义**：排第一的就是打开面板时的默认页。
4. **屏蔽关键词预设**：设置页点按钮就能添加常用广告词。

## 一、新访客观察期

### 规则

- **开始**：访客**通过人机验证的那一刻**（所有写入 `verified:{uid}`、表示验证通过的地方，包括表情、题目、贴纸、Turnstile 各模式），写入 KV `probation:{uid}` = `{"left": 3, "until": <毫秒时间戳>}`，`expirationTtl` 取观察期时长。
  - **不追溯老访客**：本版本上线前已经验证过的访客，没有 `probation:*` 键，不受影响。
  - 设为「⭐ 永久信任」的访客、管理员：不进入观察期。站长把某人设为永久信任时，删除他的 `probation:{uid}`。
- **观察期内每条消息**（在决定转发之前，也就是调用 `processVisitorMessage` 之前）：
  1. 用 `assessIncomingRisk` 加上下面新增的检测，判断消息是否可疑。
  2. **不可疑**：照常转发，`left` 减 1。减到 0，或者已经超过 `until`，就删除 `probation:{uid}`，观察期结束。
  3. **可疑**：**扣下不转发**，进入「待审核」（见下文）。被扣下的消息**不计入** `left`。
- **可疑的判断**（命中任意一项即可）：
  - `hasLink`（含 `t.me`、`wa.me` 等），**但链接全部属于白名单域名时不算**；
  - 转发来的消息（`isForwarded`）；
  - 文字里有 `@用户名`（`mention` 实体或 `@[A-Za-z0-9_]{5,}`）；
  - 联系方式：手机号（连续 7 位以上数字，允许中间有空格或横线）、「微信 / VX / wx / 加我 / 联系我」后面跟着账号样式的字符串；
  - 媒体（图片、视频、文件、贴纸）**不算可疑**，因为 `blockUnverifiedMedia` 已经处理了未验证阶段，验证后的正常访客发图很常见。
- **屏蔽关键词照旧优先**：命中关键词的消息仍然直接丢弃，不进入待审核。

### 待审核：存储

- 每条被扣下的消息存一份精简记录：`{ pmMessageId, chatId, preview, reasons, at }`。`preview` 取文字前 300 字，没有文字就用媒体标签。
- 存放位置：访客记录 `user:{uid}` 新增字段 `pendingReview: [...]`，最多保留 10 条，**复用已有的访客记录写入**。另外在访客摘要（`listVisitors` / `cache:visitor_summary`）里加上 `stats.pendingReview`：待审核的访客数。
- 失效：待审核记录保留 7 天，超过 7 天的在读取时自动丢弃（Telegram 只允许 48 小时内撤回，但复制消息没有时限）。

### 待审核：通知站长

扣下消息时，按现有的通知方式（`resolveInboxMode`）发一条**静默**消息（`disable_notification: true`）：

- **话题模式**：发到这个访客的话题里；
- **私聊推送模式**：发到主人私聊。

```text
🛡️ 新访客消息待审核
原因：含链接 · 含联系方式
内容：<preview，HTML 转义；链接用 <code> 包起来，不让 Telegram 生成可点击链接>
[ ✅ 放行 ]  [ 🚫 拉黑 ]
```

- 同一个访客**连续被扣多条**时，10 分钟内只发一次通知，之后的只累计到面板里，避免刷屏。
- 按钮的 `callback_data`：`rv:ok:<uid>` / `rv:ban:<uid>`。在 `handleCallbackQuery` 里处理，**必须先校验点击者是管理员**（`isUserAdmin`）。
- **放行**：
  1. 按顺序，把该访客 `pendingReview` 里的每条消息，用原来的转发流程（`deliverVisitorMessage`）补发给站长：用 `chatId` 和 `pmMessageId` 构造消息对象，参照 `flushPendingMessages` 的做法。
  2. 清空 `pendingReview`，删除 `probation:{uid}`（放行一次即视为可信）。
  3. 把通知消息改成「✅ 已放行」，去掉按钮。
- **拉黑**：调用现有的 `applyVisitorAction(env, uid, 'ban')`，清空 `pendingReview`，通知消息改成「🚫 已拉黑」，并调用 `recordBlockedSpam`。
- 面板里也可以操作（见第二节），两处操作要互相同步：面板处理后，通知消息上的按钮再点就提示「已处理」。

### 设置项

`DEFAULT_CONFIG.pmBot.probation`：

```js
probation: {
  enabled: true,        // 默认开启
  maxMessages: 3,       // 1–20
  hours: 24,            // 1–168
  allowDomains: [],     // 链接白名单，例如 ['github.com', 'example.com']，匹配域名本身及其子域名
},
```

- 在 `config.js` 里做合并和范围钳制，写法参照现有 `pmBot` 字段。
- 设置页「防骚扰验证」分区新增「新访客观察期」块：开关、条数、小时数、白名单域名（每行一个）。下面加一行说明：「刚通过验证的访客，前几条消息如果带链接、@用户名、联系方式或是转发的，会先扣下等你审核，不会丢失。」

## 二、首页提示条与访客页调整

### 首页（`web/src/components/TicketTab.jsx`）

- **删除**名片下面整块「站长速览」卡片（`isAdmin && visitorSummary` 那一段：统计块、「最近联系」列表、「近期更新」按钮）。
- 换成**一行提示条**，只有管理员能看到：
  - 有待审核：`🛡️ N 位新访客的消息待审核 ›`，用醒目样式（强调色背景）。点击跳到「访客」页，并自动选中「待审核」筛选。
  - 没有待审核：`🛡️ 防护正常 · 今日拦截 N 次 ›`，淡色小字。点击跳到「访客」页。
- 「近期更新」入口去掉即可：设置页已有「版本更新」，升级后也会自动弹出更新弹窗。

### 今日拦截计数

- `recordBlockedSpam` 在累加 `stats:blocked_spam`（累计总数，保留）的同时，累加 `stats:blocked:<YYYYMMDD>`，`expirationTtl` 3 天。
- 「今天」按站长时区计算，复用 `config.community.timezoneOffsetHours`（和签到、本月访客数一样，可参考 `src/worker/visitStats.js` 的 `getMonthKeys`）。
- bootstrap 接口给管理员返回 `blockedToday` 和 `pendingReviewCount`。

### 访客页（`web/src/components/VisitorsTab.jsx`）

- 顶部统计区加上「已拦截广告 N 次（累计）」，也就是原来首页那个统计块。
- 筛选 chips 新增「待审核」，带数量角标，和「全部 / 活跃 / 已关闭 / 封禁」并列。`listVisitors` 支持 `filter=pending`。
- 访客详情里，有待审核消息时在顶部显示这些消息的预览，以及「✅ 放行」「🚫 拉黑」两个按钮。新增接口 `POST /api/admin/visitors/:uid/review`，请求体 `{ action: 'approve' | 'ban' }`，逻辑和通知按钮共用同一个函数。
- 底部导航「访客」图标上，有待审核时显示数量小红点。

## 三、导航顺序可自定义

- 配置：`DEFAULT_CONFIG.ui = { navOrder: ['profile', 'sites', 'probe', 'visitors', 'leaderboard'] }`。
  - 校验：只接受已知的标签 ID，去重；缺少的已知 ID 按默认顺序补在后面。
  - 老配置没有 `ui` 字段时，取默认值，**升级后顺序不变**。
  - `navOrder` 放进公开配置，访客也需要它来决定默认页。它不含敏感信息。
- `web/src/App.jsx`：`navItems` 照现有逻辑生成，包括各标签页的开关条件和访客页只对管理员显示，然后**按 `navOrder` 排序**。
- **默认页 = 排序后第一个可见的标签页**。访客看不到的标签页（「访客」、设为「仅自己可见」的探针、未开启的签到榜单）自动跳过。
  - 例如站长把「访客」排第一：站长打开面板默认进访客页，访客打开仍默认进名片。
- **深链接优先**：通过 `start_param` 或 `?tab=` 打开指定页面时（海报二维码、通知按钮、`visitor_<uid>` 等），照常打开指定页面，不受排序影响。
- 设置页新增「导航顺序」块：列出当前可用的标签页，每项有「上移」「下移」按钮，**不用拖拽**（手机上拖拽容易误触）。标题下注明「第一个是打开面板时的默认页；访客看不到的页面会自动跳过」。

## 四、屏蔽关键词预设

纯前端改动（`web/src/components/SettingsDrawer.jsx`），后端不变。

- 在「屏蔽关键词」输入框上方显示分组预设按钮。点一下加入输入框，再点一下移除，已加入的高亮。每组有「整组添加」。
- 预设词放在一个常量里，例如 `web/src/lib/keywordPresets.js`：

  | 分组 | 预设词 |
  | :--- | :--- |
  | 💰 币圈投资 | USDT返利, 稳赚不赔, 带单, 合约喊单, 空投领取 |
  | 🎰 博彩 | 菠菜, 博彩, 彩票计划, 百家乐, 充值返水 |
  | 💼 兼职刷单 | 日结兼职, 刷单, 点赞赚钱, 手机兼职, 宝妈兼职 |
  | 📢 引流推广 | 加微信领取, 免费送粉, 互粉, 涨粉 |
  | 🔞 色情 | 约炮, 同城约, 福利视频, 裸聊 |
  | 🌐 英文广告 | earn money fast, crypto signal, investment opportunity, forex signal |

- **只放广告特有的短语，不要放「代理」「推广」「投资」「兼职」这类单个日常词**：命中关键词的消息会被悄悄丢弃，误伤代价大。
- **默认一个都不选**，升级不会改变站长现有的关键词。
- 增删预设词时，保持站长手填的其他词不变，逗号分隔格式不变。总长度仍受现有 2000 字符限制。注意现有匹配会经过 `normalizeAntiSpamText` 处理，预设词要能在处理后正确匹配（例如中文不受影响、英文大小写不敏感），写测试确认。
- 输入框下方提示：「命中的消息会被直接丢弃，你和对方都不会收到提示。建议只添加广告特有的短语；熟人可设为永久信任，不受关键词限制。」

## 六、测试（`tests/worker.test.js`）

现有测试一个都不能删、不能改弱。新增：

1. 验证通过后写入 `probation:{uid}`；永久信任、管理员不写；老访客（没有该键）不受影响。
2. 观察期内：带链接、`@用户名`、手机号或微信号、转发的消息被扣下，**不调用任何转发**，写入 `pendingReview`，并发送带按钮的静默通知；普通文字照常转发并让 `left` 减 1；减到 0 后删除 `probation:{uid}`。
3. 白名单域名的链接不算可疑，子域名也匹配；`evilgithub.com` **不能**匹配 `github.com`。
4. 同一访客 10 分钟内连续被扣，只发一次通知。
5. 放行：按顺序补发全部待审核消息，清空列表，删除观察期；拉黑：调用拉黑、清空列表、计入拦截次数。**非管理员点按钮被拒绝。**面板接口和按钮两种方式结果一致。
6. 屏蔽关键词仍然优先，命中的直接丢弃，不进待审核。
7. 今日拦截计数：按站长时区跨日正确，带 `expirationTtl`；累计总数照常增加。
8. `navOrder` 校验：未知 ID 被丢弃、去重、缺少的补齐；老配置取默认顺序；公开配置包含 `navOrder`。
9. 关键词预设：每个预设词经过现有归一化后都能命中对应文本（写一个参数化测试遍历全部预设词）。

**验收**：`npm test && npm run build` 全部通过。
